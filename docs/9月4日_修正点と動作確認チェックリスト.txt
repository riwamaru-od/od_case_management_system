0. 事前作業（必ず最初に実施してください）
==========================================================================

今回の修正で案件シートの列が 32列（AF列まで）から 36列（AJ列まで）に
増えています。列を拡張するまでサイドバーがエラーになりますので、
必ず 0-1 から順に実施してください。

[ ] 0-1. 案件シートの列を拡張する
     手順: メニュー「管理者用メニュー」→「案件シートの構成を確認・修復する」
     期待: 完了ダイアログに以下が表示される
           ・xx期_表示、xx期_全案件DB、原本_表示、原本_全案件DB の4シート
           ・「列数を 32 → 36 へ拡張」
           ・「見出しの行: 表示シート=2行目 / 全案件DB=1行目」

[ ] 0-2. 追加された4列の見出しを確認する
     期待: 表示シートは 2行目、全案件DBは 1行目 に以下が入っている
           AG列「見積書再承認待ち」
           AH列「請求書再承認待ち」
           AI列「見積書着手日時」
           AJ列「請求書着手日時」
     注意: 表示シートの1行目（見出しの1段目）は書き換わっていないこと

[ ] 0-3. シートの保護範囲を AJ列まで広げる
     手順: 表示シート・全案件DBシートそれぞれで、保護範囲を AJ列 まで拡張
     理由: 新しい4列もシステムが自動で書き込む列のため

[ ] 0-4. トリガーを再登録する（管理用アカウントで実施）
     手順: 拡張機能 → Apps Script → 関数「installTriggers」を選択して実行
     期待: トリガー一覧に以下の3つが登録されている
           ・onEditInstallable（スプレッドシート・編集時）
           ・dailyScheduledTasks（時間主導型・午前0時〜1時）
           ・morningScheduledTasks（時間主導型・午前10時〜11時）★今回追加

[ ] 0-5. メニューの表示を確認する
     手順: スプレッドシートを再読み込みする
     期待: メニューが2つに分かれている
           「ユーザー用システム設定」… サイドバーを開く／自動表示の有効・解除
           「管理者用メニュー」… 社印設定／構成の確認・修復／WebアプリURL設定／
                                 バックアップ／アーカイブ

1. 見積と請求の内容差分を黄色で表示（修正内容1）
==========================================================================

請求書は見積書の内容をコピーして作られます。作成後に請求書側だけが
編集されて見積書と食い違った場合、そのセルが自動で黄色になります。

対象セル
  B5〜B8    郵便番号・住所1・住所2・会社名（取引先DB由来）
  B10、B11  部署・担当者名（取引先DB由来）
  G1        案件番号
  C16       件名
  G12、G13  担当社員の氏名・メールアドレス（社員DB由来）
  B22:E47   明細
  E49、F50、F53
  ※ G6（請求書の通し番号）、G53（見積書No.の参照）は対象外です

[ ] 1-1. 作成直後は色が付いていないこと
     手順: 見積書を承認 → 請求書を作成 → 請求書を開く
     期待: 上記のセルに黄色が付いていない（見積書と一致しているため）

[ ] 1-2. 内容を変えると即座に黄色になること
     手順: 請求書の明細（例: B22）の値を書き換える
     期待: 入力を確定した瞬間にそのセルが黄色になる
           （ボタン操作や画面の再読み込みは不要）

[ ] 1-3. 元に戻すと黄色が消えること
     手順: 1-2 で変えたセルを、見積書と同じ値に戻す
     期待: 入力を確定した瞬間に黄色が消える

[ ] 1-4. 取引先情報を変えても黄色になること
     手順: 請求書の会社名（B8）や担当者名（B11）を書き換える
     期待: そのセルが黄色になる

[ ] 1-5. 黄色がPDFに出ないこと ★重要
     手順: 1-2 の状態（黄色が付いた状態）のまま、請求書を承認してPDF出力する
     期待: 出力されたPDFに黄色が付いていない
           （差分の黄色は社内確認用で、取引先へ渡すPDFには出しません）

[ ] 1-6. 再作成しても機能が引き継がれること
     手順: 請求書を差し戻し → 再作成 → 内容を書き換える
     期待: 再作成後の請求書でも黄色が付く

[ ] 1-7. 非表示シートが増えていること
     手順: 請求書ファイルで、シート見出しを右クリック →「非表示シート」を確認
     期待: 「_見積比較用」という非表示シートがある
           （比較用の内部データです。編集・削除しないでください）

全書類とも、本文の1ページのみを出力するようになりました。
操作履歴欄（56行目以降）と、見積書の請求書発行情報（I〜P列）は

[ ] 2-4. 社印がPDFに写っていること

[ ] 2-5. 内容が切れていないこと
     期待: 明細・金額・宛名など、本文の内容が欠けたり見切れたりしていない

3. 再承認までPDF出力・後続書類の作成を止める（修正内容3）
==========================================================================

差し戻し・再作成をすると「再承認待ち」の状態になり、再度承認されるまで
PDF出力と後続書類の作成ができなくなります。古い版のPDFが出回るのを防ぐためです。

[ ] 3-1. 差し戻すとPDF出力ボタンが押せなくなること
     手順: 見積書を承認 →（PDF出力ボタンが押せることを確認）→ 再作成 → 差し戻し
     期待: 「見積書PDF出力」ボタンが非活性
           マウスを乗せると「再作成・差し戻し後は、再度承認されるまで出力できません」

[ ] 3-2. 再作成するとPDF出力ボタンが押せなくなること
     手順: 見積書を承認 → 再作成
     期待: 「見積書PDF出力」ボタンが非活性

[ ] 3-3. 再承認するとPDF出力ボタンが戻ること
     手順: 3-2 の状態から、完成 → 承認
     期待: 「見積書PDF出力」ボタンが再び押せる

[ ] 3-4. AG列に日時が入り、承認で消えること
     期待: 差し戻し・再作成した時点で AG列「見積書再承認待ち」に日時が入り、
           再承認すると空になる

[ ] 3-5. 承認日時の履歴が消えていないこと ★重要
     期待: 再作成・差し戻しをしても、R列「見積書承認日時」の値は残っている
           （サイドバーの操作履歴にも前回の承認記録が残っている）

[ ] 3-6. 再承認待ちの見積書から請求書を作れないこと
     手順: 見積書を承認 → 再作成 → サイドバーを見る
     期待: 「請求書作成」ボタンが非活性
           「見積書が再作成・差し戻し中です。再度承認されてから操作してください」

[ ] 3-7. 再承認待ちの請求書から納品書を作れないこと
     手順: 請求書を承認 → 再作成 → サイドバーを見る
     期待: 「納品書作成」ボタンが非活性

[ ] 3-8. 請求書についても 3-1〜3-5 と同じ動作になること
     期待: AH列「請求書再承認待ち」で同様に制御される

4. 書類ファイルの二重生成を防ぐ（修正内容4）
==========================================================================

同じ案件のファイルが2つできてしまう事象への対策です。
原因は未特定のため、発生を検知できるようにログを残します。

[ ] 4-1. 通常の作成が問題なく動くこと
     手順: 見積書・請求書・納品書をそれぞれ作成する
     期待: 各案件フォルダにファイルが1つだけできる

[ ] 4-2. 二重作成が起きていないこと（テスト期間中は毎回確認）
     手順: 書類を作成するたびに、案件フォルダの中を確認する
     期待: ファイルが1つだけ

[ ] 4-3. 二重実行の記録が出ていないか確認する ★重要
     手順: テスト期間の終わりに、操作ログを「二重実行」で検索する
     期待: 該当なし
     もし記録があった場合: その行の日時・案件番号・操作種別を控えてください。
           「既に作成済みのため作成をスキップしました（二重実行の防止）」
           = 二重リクエストが実際に発生し、ガードが働いた記録です。
           根本原因の調査材料になりますので、必ずご連絡ください。

[ ] 4-4. 再作成でシートが2枚増えていないこと
     手順: 見積書を再作成し、ファイル内のシート一覧を確認する
     期待: 「見積書_最新」1枚と、退避された「見積書_v1_日付」1枚のみ

5. 案件中止時の処理（修正内容5）
==========================================================================

[ ] 5-1. 見積書が無い案件を中止すると、見積書が自動作成されること
     手順: 見積書を作成していない案件で「案件中止」を実行
     期待: 見積書が自動で作成される（完成・承認依頼は行われない）
           操作ログに「見積書が未作成だったため自動作成しました」が残る

[ ] 5-2. 中止した案件のフォルダが移動すること ★重要
     手順: 書類を一通り作成した案件を中止する
     期待: 3書類とも、案件フォルダが「中止案件」フォルダ配下へ移動している
           見積書 → 見積書/xx期/中止案件/{案件番号}_{案件名}/
           請求書 → 請求書/xx期/中止案件/{案件番号}_{案件名}/
           納品書 → 納品書/xx期/中止案件/{案件番号}_{案件名}/

[ ] 5-3. 元のフォルダからは消えていること
     期待: 「未請求案件」「請求中案件」フォルダに、中止した案件のフォルダが残っていない

[ ] 5-4. 中止案件が表示シートから消え、全案件DBには残ること
     期待: 表示シートから行が削除され、全案件DBにはステータス「中止」で残っている

[ ] 5-5. 操作ログに移動内容が残ること
     期待: 「案件中止」の詳細欄に「中止案件フォルダへ移動: 見積書・請求書・納品書」

6. 定期通知（修正内容6）
==========================================================================

送信時刻はいずれも午前10時です。

[ ] 6-1. 未承認案件レポートが届くこと（毎月25日 午前10時／総務宛）
     手順: 25日を待つか、スクリプトエディタから
           「sendUnapprovedSummaryReportIfNeeded_」を手動実行して確認
           ※手動実行時は当日が25日でないと送信されません。
             動作だけ見たい場合は「morningScheduledTasks」を実行してください
     期待: 総務ロール保持者全員にメールが届く。件名「【未承認案件レポート】○年○月○日時点」
           本文に2つの表がある
           ・書類が未承認の案件（作成中・承認待ちの両方）
           ・請求済みだが最終承認が未完了の案件

[ ] 6-2. 未承認一覧の中身が正しいこと
     期待: ステータスが「見積書作成中」「見積書承認待ち」「請求書作成中」
           「請求書承認待ち」の案件が漏れなく載っている
           中止済みの案件は載っていない

[ ] 6-3. 請求済み未承認一覧の中身が正しいこと
     期待: 請求ステータスが「請求済み」の案件が載っている
           最終承認済みの案件は載っていない

[ ] 6-4. 放置書類アラートが届くこと（毎日 午前10時／案件の担当者宛）
     手順: AI列「見積書着手日時」を8日以上前の日時に手で書き換えてから、
           スクリプトエディタで「sendStalledDocumentAlertsIfNeeded_」を実行
     期待: その案件の担当者に通知が届く
           件名「【要対応】作成中のまま7日以上経過した書類があります（○件）」
           本文に案件番号・書類種別・着手日時・経過日数が載っている
     注意: 総務ロールの人はメール、それ以外の人はChatworkに届きます

[ ] 6-5. 着手日時が記録されていること
     期待: 書類を作成すると AI列／AJ列に着手日時が入る。再作成でも更新される

[ ] 6-6. 対象が無い日は何も送られないこと
     期待: 7日以上経過した書類が無い日は、アラートメールが届かない

7. 見積書の承認依頼先を指定する（修正内容7）
==========================================================================

[ ] 7-1. 承認者のプルダウンが出ること
     手順: 見積書の「完成」ボタンを押す
     期待: コメント欄の上に「承認者の指定（任意）」プルダウンがある
           選択肢に「指定しない（総務全員へ依頼）」と、承認権限を持つ社員の氏名が並ぶ
           （「見積書承認」「Admin」「総務」いずれかのロールを持つ人）

[ ] 7-2. 請求書ではプルダウンが出ないこと
     手順: 請求書の「完成」ボタンを押す
     期待: プルダウンが表示されない（コメント欄のみ）

[ ] 7-3. 未指定なら従来どおり総務全員へ届くこと
     手順: 「指定しない」のまま実行する
     期待: 総務ロール保持者全員に、通常の件名でメールが届く
           件名「【承認依頼】案件名（見積書）」

[ ] 7-4. 指定した本人に届くこと
     手順: 承認者を指定して実行する
     期待: 指定した本人に通知が届く（件名に前置きは付かない）

[ ] 7-5. 指定されていない総務には前置きが付くこと ★重要
     手順: 7-4 の状態で、指定されなかった総務メンバーの受信箱を確認する
     期待: 件名の先頭に「*承認者指定済み*」が付いている
           「*承認者指定済み* 【承認依頼】案件名（見積書）」

[ ] 7-6. 指定した本人が総務の場合の動き
     期待: その人には前置き無しの件名、他の総務メンバーには前置き付きの件名が届く

[ ] 7-7. 承認権限が無い人を指定できないこと
     期待: プルダウンに、承認権限を持たない社員は出てこない

[ ] 7-8. 承認完了通知に承認者名が入ること
     手順: 見積書を承認し、依頼者（作成者）宛の通知を確認する
     期待: 本文に「承認者: ○○」が入っている
     ※ 請求書の承認完了通知にも同様に入ります

[ ] 7-9. 操作ログに指定内容が残ること
     期待: 「見積書完成（承認依頼）」の詳細欄に「承認者指定: ○○」

8. 見積書の作業用エリア（J21:O54）
==========================================================================

[ ] 8-1. 承認後も編集できること
     手順: 見積書を承認したあと、J21:O54 の範囲に文字を入力してみる
     期待: 保護の警告が出ず、そのまま入力できる

[ ] 8-2. 承認後、本文は編集できないこと
     手順: 同じ見積書で、A1:H54 の範囲（例: 明細欄）を編集してみる
     期待: 「保護されているセル」の警告が出て編集できない

[ ] 8-3. PDFに影響しないこと
     期待: J21:O54 に文字を入れてもPDFには出力されない（出力範囲は A1:H54 のため）

     ※ 差し戻された見積書と、再作成で退避された旧版シートは、
       J21:O54 も含めて全体が保護されます（過去の記録として固定するため）。
       ここも編集したい場合はご連絡ください。

9. 終了予定・請求予定・担当の変更記録
==========================================================================

[ ] 9-1. 変更が操作ログに残ること
     手順: 採番済みの案件で、表示シートの「終了予定」を別の値に変更する
     期待: 操作ログに1行増える
           操作種別「案件情報の変更」
           詳細「終了予定: 2026/09 前半 → 2026/10 後半」（変更前 → 変更後）

[ ] 9-2. 請求予定・担当も同様に記録されること
     手順: 「請求予定」「担当」をそれぞれ変更する
     期待: それぞれ操作ログに記録される

[ ] 9-3. 全案件DBに反映されること ★重要
     手順: 9-1 の変更後、全案件DBの該当行を確認する
     期待: 変更後の値が反映されている

[ ] 9-4. 未採番の行では記録されないこと
     手順: 案件番号が未採番の行に、終了予定などを入力する
     期待: 「案件情報の変更」のログは出ない
           （5項目が揃った時点で「案件登録（自動採番）」のログが出る）

[ ] 9-5. 実行者欄の表示を確認する
     期待: 実行者欄が「シート直接編集（実行者不明）」になっている
     ※ この環境ではGoogleが編集者の身元をスクリプトに渡さないため、
       シートを直接編集した人は特定できません（仕様として合意済み）。
       誰が変更したかを追う必要がある場合は、スプレッドシートの
       「ファイル → 変更履歴を表示」で確認してください。

[ ] 9-6. 複数セルを一括で貼り付けた場合
     期待: ログの詳細が変更後の値のみになる（「終了予定: 2026/10 後半」）
           ※ Googleが変更前の値を渡さないための制約です

10. 回帰確認（既存機能が壊れていないこと）
==========================================================================

今回は列の追加とPDF範囲の変更を行ったため、基本の流れを一通り確認してください。

[ ] 10-1. 案件の自動採番
     手順: 表示シートの3行目以降に、取引先名・案件名・終了予定・請求予定・担当を入力
     期待: 案件番号が採番され、ステータス「案件登録済み」、請求ステータス「未請求」

[ ] 10-2. 見積書の一連の流れ
     期待: 作成 → 完成（承認依頼）→ 承認 → PDF出力 が問題なく通る

[ ] 10-3. 請求書の一連の流れ
     期待: 作成 → 完成 → 承認 → PDF出力 が問題なく通る
           承認時に案件フォルダが「未請求案件」→「請求中案件」へ移動する

[ ] 10-4. 納品書の流れ
     期待: 作成 → PDF出力 が問題なく通る（納品書に承認ステップはありません）

[ ] 10-5. 最終承認
     期待: 請求書・納品書のPDF出力後に「最終承認」が押せる
           最終承認すると表示シートから行が消え、全案件DBには残る

[ ] 10-6. 書類のオーナーが管理用アカウントであること ★重要
     手順: 一般社員アカウントで書類を作成し、ファイルの詳細を確認する
     期待: オーナーが管理用アカウント（odcloud@over-dlive.co.jp）になっている

[ ] 10-7. 操作ログの実行者がボタンを押した本人であること
     手順: 一般社員アカウントでサイドバーの各ボタンを操作する
     期待: 操作ログの実行者欄に本人の氏名が入っている
           （「システム(自動実行)」や管理用アカウント名になっていないこと）

[ ] 10-8. 社印が正しく押されること
     期待: 見積書・請求書は承認時、納品書は作成時に社印が入る

[ ] 10-9. 「今月請求」のハイライト
     期待: 請求予定が今月の行の文字色が変わっている

[ ] 10-10. 終了予定・請求予定のプルダウン
     期待: 表示シートの3行目以降で、D列・E列にプルダウンが出る

11. 既知の制約（仕様としてご了承いただいている点）
==========================================================================

・シートを直接編集した人は特定できません（9-5 参照）。
  Google Workspaceを契約していない環境のため、Googleがスクリプトに
  編集者の身元を渡さないことによる制約です。

・複数セルを一括で貼り付けた場合、変更前の値がログに残りません（9-6 参照）。

・書類の二重生成の根本原因は未特定です。ガードにより症状は止まりますが、
  発生した場合は操作ログに記録が残ります（4-3 参照）。

・見積書の作業用エリア（J21:O54）の保護除外は、今回の変更以降に承認された
  書類から有効です。既に承認済みの見積書には遡って適用されません。

・コードを変更した際は、Webアプリの再デプロイが必要です（サイドバーの
  書き込み操作はWebアプリ経由で管理用アカウント権限で実行されるため）。
